# Fleet v0.2.1

Date: 2026-09-22

> **Version note.** This branch is cut from `main` and is independent of
> `feat/typescript-symbol-graph` (v0.2.0) — no shared files, and the change works on a Rust repo
> with or without it. It is numbered 0.2.1 on the assumption that 0.2.0 lands first. **If this
> merges first, renumber this note to v0.2.0 and the CHANGELOG heading with it.**

## What changed

`fleet impact --symbol <name>` now reports the functions that call the symbol, not just how many
functions carry the name.

`build_repo_map` already returned `edges: Vec<(SymbolId, SymbolId)>` — caller, callee. The command
loaded them on every invocation and never read them:

```rust
let hits = map.symbols.iter().filter(|s| s.name == args.symbol).count();
```

So `impact --symbol build` answered `5` — five functions are *named* `build` — while the repo held
26 places calling one. The count was a fact about the name, not about the blast radius.

```
$ fleet impact --repo crates --symbol write_all
```


`matching_symbols` is unchanged, so anything parsing today's JSON keeps working. `callers` is
additive.

## What the field is called, and why it is not `call_sites`

**An edge is a pair of ids and carries no call location.** The first draft of this named the field
`call_sites` and its test asserted three rows for a fixture where one function calls the target
twice on two lines. That test failed — the graph reports the *caller*, located at the caller's own
definition, not the call.

Renaming it to `callers` is the honest description of the data. `src/tests/impact_lists_callers`
pins the limit deliberately (`the_reported_line_is_the_callers_own_definition_not_the_call`), so
if the graph ever carries call locations, that test is the one that fails and says so.

One calling function is one row however many times it calls.

## Verified against a real codebase

Run on `posx-mokobara-backend/src` with `feat/typescript-symbol-graph` also applied — that branch
is what makes the walker see `.ts` at all — and cross-checked against `grep`:

| symbol | `grep`: call **locations** | `impact`: calling **functions** |
|---|---|---|
| `customerIdentityPhone` | 5 — lines 303, 339, 470, 519, 923 | **3** — `GET`@197, `POST`@359, `PUT`@711 |
| `performShopifyReturnWithRefund` | 2 — `exchange-order-post-effects.ts:240`, `return-order-confirmed.ts:271` | **2** — those two subscribers |

The first demonstrates the semantics exactly: five call locations sitting inside three handler
functions. The second independently reproduced a fact that had previously been established by
reading the code by hand.

### What this fixes in practice

`customerIdentityPhone` is the phone-identity filter that the POSX security fix (TD-B018) has to
preserve. Before this change, asking fleet who depends on it returned `1` — the definition count.
Now it names the three request handlers that would break, in one command, before any code is
written. That is the *context-free assignment* problem the estate's own pain log scores at 4–6
hours per week: a developer changes something used in N places without knowing the N.

## Known failures, blockers and unverified claims

**Pre-existing on `origin/main`, unchanged here** — previously reproduced on a pristine detached
worktree:

- `cargo clippy --workspace --all-targets -- -D warnings` fails on
  `crates/plan/src/ready_gate/gate/gate_eval.rs:45` (`manual checked division`). Nothing here is
  in `crates/plan`.
- `cargo test --workspace --no-fail-fast` fails 16 targets (15 `fleet-cli`, 1 `verify`),
  identically on `main`. Environment-shaped: the spawned binary exits non-zero before the
  assertions are reached.
- The 80-line cap is already breached by ~120 files on `main`.

**Not done, and not claimed:**

- **No call locations.** Reported lines are the caller's definition. Adding real call locations
  means carrying a position on the edge through `extract_call` and `repomap_edges` — a change to
  `crates/context`, not to this command.
- **`fleet graph` still prints three counts** and exposes neither the symbol list nor the edge
  list. Only `impact` was changed.
- **Functions only.** Types, interfaces and enums are not symbols in this graph, so
  `impact --symbol SomeType` still reports 0 with no callers.
- **A caller outside the parsed set is dropped**, not reported as unknown — a call from a
  dependency or a macro body has no file or line we can name, and emitting a placeholder would be
  inventing evidence.
- On a **TypeScript** repo this is only useful with `feat/typescript-symbol-graph` applied;
  without it the walker sees no `.ts` files and every answer is 0. The two branches are
  independent in code and complementary in effect.
- Not run here: any CI pipeline, any remote gate, any other repo's suite.

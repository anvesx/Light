# Fleet v0.2.0

Date: 2026-09-22

## What changed

`crates/context` can now parse TypeScript and TSX. Before this, `graph` and `impact` were blind
to both, because the crate carried only `tree-sitter-rust`, `-python` and `-bash`, so
`language_for` returned `None` for every `.ts`/`.tsx` file and the walker skipped it.

Minor rather than patch: `Language` is a public enum and gains two variants, which breaks an
exhaustive match downstream.

### Measured, on a real estate

`fleet graph --repo <path>`, against the POSX repos:

| Target | Before | After |
|---|---|---|
| `posx-mokobara-backend/src` (1,302 `.ts`) | 2 files · 60 symbols · 65 edges | **1,304 files · 1,486 symbols · 1,642 edges** |
| `posx-mokobara-store/src` (210 `.ts`, 248 `.tsx`) | 0 files · 0 symbols · 0 edges | **458 files · 1,216 symbols · 1,327 edges** |

The two files found before were stray `.py` scripts.

### Why the grammar was the small part

Rust has exactly one definition shape — `function_item`, carrying a `name` field — which is why
`definition()` could read name and arity generically for every supported language. TypeScript has
several, and **the dominant one carries no `name` field at all**: an arrow function's name lives
on the parent `variable_declarator`.

Counted on the POSX estate, 2026-09-22:

| Repo | `function` declarations | arrow consts |
|---|---|---|
| backend `src/` | 436 | **580** |
| storefront `src/` | 403 | **531** |

A `function_declaration`-only implementation would miss the majority of definitions in both
repos — and would look plausible while doing it, which is worse than not parsing at all.

`extract_definition_ts` therefore handles `function_declaration`,
`generator_function_declaration`, `method_definition`, and the binding forms
`variable_declarator` / `public_field_definition` whose value is an `arrow_function` or
`function_expression`. A `const` bound to a non-function is deliberately **not** a symbol;
counting it would inflate the graph with every config object in the repo.

`TypeScript` and `Tsx` are separate variants because tree-sitter ships two grammars — JSX
conflicts with type assertions, so the plain TypeScript grammar cannot parse `.tsx`. 248 of the
storefront's 458 source files are `.tsx`, so this is not optional.

## What this improves in the development lifecycle

Stated carefully, because two of the four are enabling rather than delivered.

**1. Context selection for a build lane becomes possible on a TypeScript repo.**
This is the one that matters most and it is still indirect. A `swarm` lane today is given only
the task string — nothing assembles repo context — so a caller must paste the relevant file
contents into `--prompt` by hand. That is workable for a one-file change and does not scale to a
1,302-file service. Selecting context automatically requires knowing which symbols a task touches
and what they connect to. On a TypeScript repo that information did not exist before this change.
It now exists. **It is not yet wired into dispatch**, and this release does not claim it is.

**2. Blast radius before a change, rather than after review.**
The repo's own pain log records *context-free assignment* — a developer changes something used in
eleven places — at 4–6 hours per week. Answering that needs call edges over the real codebase.
There are now 1,642 of them on the backend and 1,327 on the storefront where there were 65 and 0.
See the honest limit below: the edges exist but nothing exposes them yet.

**3. Cross-repo duplication work gets a machine-checkable handle.**
The estate's largest measured cost is five near-identical POS products carrying ~705,000
duplicated lines, 93% of it cross-brand, where one base bug is fixed up to five times or never
ported. `fleet run --repo a b c` already accepts N repos with an aggregated verdict. A symbol
graph that covers all five repos is the precondition for asking *"does this symbol exist in the
other four, and does it differ?"* mechanically rather than by grep.

**4. It closes a gap between what the estate is written in and what the tool can read.**
Fleet gates a TypeScript repo today (`.fleet/gates.toml` lets a repo declare its own commands),
but could not *read* one. A tool whose verification half understands a repo and whose analysis
half does not is hard to reason about, and the failure was silent — `files_scanned: 2` looks like
a working command, not a skipped language.

## Known failures, blockers and unverified claims

**Pre-existing on `origin/main`, unchanged by this release.** Each was reproduced on a pristine
detached worktree of `origin/main` before being attributed:

- `cargo clippy --workspace --all-targets -- -D warnings` fails on
  `crates/plan/src/ready_gate/gate/gate_eval.rs:45` (`manual checked division`). Identical on
  main. No file in this release is in `crates/plan`.
- `cargo test --workspace --no-fail-fast` fails **16 targets** (15 `fleet-cli`, 1 `verify`).
  The same 16 fail identically on main. Spot-checked
  `stream_ndjson_off_by_default`: the assertion that fails is `out.status.success()` — the
  spawned binary exits non-zero before the NDJSON assertion is reached — so these are
  environment-shaped, not assertion-shaped.
- The 80-line file cap in `AGENTS.md` is already violated by roughly 120 files on main, including
  a 517-line test. Every file touched here is under it, but the rule is not currently enforced.

**Not done, and not claimed.**

- **`impact` still reports definition counts, not call sites.** Verified against grep:
  `build` → `matching_symbols: 5` (5 definitions, **26** actual call sites); `write_all` → 2
  (2 definitions, **14** call sites). This release makes that count *correct on TypeScript*; it
  does not change what is counted.
- **`graph` still prints only three numbers.** It computes 1,642 edges on the backend and exposes
  none of them. Making those edges queryable is the change that actually answers *"what breaks if
  I touch this"* — this release is what makes such an answer cover the estate's real languages.
- **Nothing is wired into dispatch.** A build lane still receives no assembled context.
- `impact --symbol` matches **functions only**. Types, interfaces and enums return 0 — true on
  Rust before this change, and still true for TypeScript now.
- POSX's dominant backend idiom
  (`export const fooStep = createStep("id", async (input, { container }) => { … })`) is recorded
  under the binding name `fooStep`, which is correct, but no wrapper-aware naming was added.
- Not run here: any CI pipeline, any remote gate, any other repo's suite. Local macOS,
  Apple Silicon, `FLEET_LANE_BUDGET_MB=1024` on the workspace run because this machine sits within
  ~40 MB of the 2,048 MiB per-lane floor.
